# Leafwise

**Crop disease detection that works with the network off.**

A 9 MB classifier runs entirely inside the browser — 38 disease classes across 14 crops,
~6 ms per inference, no upload, no account, no server to keep alive.

## The problem this is shaped around

Plant-disease demos are usually a notebook with a 99% accuracy claim and a Colab link. That
number comes from PlantVillage — one leaf, plain background, even light — and it collapses on
a photo taken in an actual field. Meanwhile the people who need the tool are standing in that
field, often with one bar of signal or none.

So Leafwise makes two commitments:

1. **Inference happens on the device.** The model is fetched once and cached; after that the
   app works in airplane mode. There is no inference server anywhere in this repository.
2. **Both accuracy numbers get published.** In-distribution *and* cross-dataset, measured by
   a script in this repo that writes the JSON the site renders.

## What it does

| | |
| --- | --- |
| **Diagnose** | Camera or photo → top-3 classes with probabilities, in about 6 ms of compute |
| **Explain** | Every condition maps to field notes: how to confirm it by eye, what to do today, how it spreads, what to change next season |
| **Flag uncertainty** | Anything under 45% is labelled low-confidence instead of being presented as a diagnosis |
| **Remember** | Scans are stored in IndexedDB with a thumbnail and export as CSV |
| **Install** | A real PWA: add to home screen, then turn mobile data off |

## Measured accuracy

Reference host: Intel i5-11400H, ONNX Runtime CPU, 2 threads. Generated by
`tools/evaluate.py`, which writes `web/public/model/benchmarks.json` — the same file the
website reads, so the published numbers cannot drift from the measured ones.

| Suite | Dataset | Images | Top-1 | Top-3 | Crop only | Latency |
| --- | --- | --- | --- | --- | --- | --- |
| In-distribution | PlantVillage (held-out test split) | 200 | **94.0%** | 99.5% | 97.9% | 5.9 ms |
| Cross-dataset | PlantDoc (field photography) | 200 | **18.5%** | 38.5% | 52.0% | 11.9 ms |

**That gap is the most important number in this repository.** 94% becomes 18.5% when the same
model sees leaves photographed in a real field instead of on a lab bench. It still gets the
crop right about half the time, and the confusions are systematic rather than random — TYLCV
curl gets read as late blight, bacterial spot as grape black rot. A model trained on studio
images has learned studio images.

That is why the app flags anything under 45% as low-confidence, shows the second and third
guesses, and tells you to re-shoot instead of presenting a single answer. Closing this gap
needs fine-tuning on field imagery, which is the next piece of work, not a caption.

Caveat on the cross-dataset row: the sampled PlantDoc shard is tomato-dominated, so treat
18.5% as a tomato-weighted estimate rather than a balanced 38-class score.

Most common in-distribution confusions, straight from the harness:

- `soybean/healthy → bellpepper/healthy` — plain green leaves are genuinely ambiguous at 224 px
- `tomato/target spot → tomato/spider mites` — both present as small scattered lesions
- `corn/gray leaf spot → corn/northern leaf blight` — the same lesion shape at different scales

## How it works

```
camera frame
   │  centre-crop to square, resize to 224 (canvas)
   ▼
Float32 CHW 0-255  ──►  MobileNetV2 ONNX (9.25 MB)  ──►  softmax over 38 classes
   │                    normalisation folded into the graph        │
   │                    ONNX Runtime Web · WASM SIMD · 1 thread    ▼
   │                                                     top-3 + guidance lookup
   ▼
IndexedDB history (thumbnail + prediction)      Cache API (model + shell, immutable)
```

Design decisions worth calling out:

- **Normalisation lives inside the ONNX graph.** The browser hands over raw RGB in 0-255.
  Mean/std constants exist in exactly one place, so the classic "works in Python, garbage in
  the app" failure mode is impossible. Export asserts torch↔onnxruntime drift (measured:
  1.6e-07).
- **Single-threaded WASM, deliberately.** Multi-threaded ORT needs cross-origin isolation
  headers, which break installability and embedding. MobileNetV2 at 224 px does not need
  threads: ~6 ms on a laptop, tens of ms on a mid-range phone.
- **Two cache strategies in the service worker.** The model and wasm binaries are immutable
  and cached forever; the shell is network-first so deploys land immediately when there is
  signal, and still open when there is not.
- **The label map is generated, not typed.** `tools/export_model.py` derives crop/condition
  splits from the checkpoint's own labels and writes `labels.json`; the guidance table is keyed
  off the condition string, and CI asserts the two stay consistent.

## Run it

```bash
git clone https://github.com/shahriar-ahmed-seam/leafwise.git
cd leafwise/web
npm install          # also stages the ONNX Runtime wasm files into public/ort
npm run dev          # http://localhost:3100
```

The model and its label map are committed (`web/public/model/`), so the app runs immediately.

To regenerate the model or the benchmarks:

```bash
cd tools
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # torch CPU wheels, ~250 MB, build-time only
.venv/Scripts/python export_model.py               # HF checkpoint -> ONNX + labels.json
.venv/Scripts/python evaluate.py --images 200      # -> benchmarks.json (both suites)
.venv/Scripts/python make_icons.py                 # PWA icon set
```

## Repository layout

```
web/
  src/app/            landing page (renders benchmarks.json) · /scan · OG image
  src/components/     ScanConsole (camera, inference, results, history) · ui
  src/lib/            classifier (ONNX Runtime Web) · guidance · history (IndexedDB) · types
  public/model/       leafwise.onnx · labels.json · benchmarks.json
  public/sw.js        two-strategy service worker
  scripts/            stages onnxruntime-web wasm into public/ort
tools/
  export_model.py     HF checkpoint -> ONNX, normalisation folded in, parity asserted
  evaluate.py         parquet-based two-suite evaluation -> benchmarks.json
  make_icons.py       PWA icons
```

## Limits

- **Fourteen crops, 38 classes.** Anything outside them still returns a confident-looking
  answer — that is how softmax behaves. The UI surfaces the second and third guesses and
  flags sub-45% results rather than hiding them.
- **Trained on studio images.** Field photos are measurably harder; that is published rather
  than hidden.
- **One leaf per frame.** Whole-plant shots dilute the prediction.
- **Not agronomic advice.** The guidance names no product or dose: those depend on local
  regulation and crop stage. Confirm with an extension service before spending money.

Next levers: static INT8 quantisation (~4x smaller, faster on phones), a "not a leaf"
rejection head so out-of-domain photos are refused instead of classified, and fine-tuning on
field imagery to close the cross-dataset gap.
